# Contributing

Report reproducible issues through [GitHub Issues](https://github.com/ofaruka/hypervisor/issues). Include the commit or release, CPU model, Windows build, toolchain versions, and the steps that produced the problem. For build failures, include the first error and the relevant part of the build log.

For runtime failures, describe the loading environment and include a focused debugger trace if available. Remove credentials, private addresses, signing material, and personal information before posting. Memory dumps can contain sensitive data; do not attach a full dump to a public issue.

Keep proposed changes focused on one problem. Explain the behavior before and after the change, identify which backend it affects, and state what was built or tested. Distinguish compilation checks from runtime tests on hardware.

Discuss substantial changes in an issue before preparing a large patch. The repository has no project license or contributor license agreement; submitting a patch does not establish new license terms for the project.
